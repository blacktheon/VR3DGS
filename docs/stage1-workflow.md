# Stage 1: installed baseline and worker foundation

Implemented in this milestone: the pinned gsplat-unity renderer, the full original model in `Assets/Scenes/Stage1.unity`, source validation, exact integer count contracts, isolated Python/CUDA setup, and the Unity job-control window. Contribution scoring, ranked subsets, A/B controls, recording, export and reimport equivalence are subsequent milestones; their tabs currently explain that status.

Open **Tools → Splats → Stage 1 Preprocessor**. In **Setup**, choose the original PLY and select **Inspect full source**. Inspection scans every row, rejects invalid input without dropping splats, hashes the source and saves the manifest. The latest successful result remains available if a later job fails or is cancelled. The **Review** tab selects the existing scene model and shows uploaded/total counts.

Use **Install / repair worker dependencies** on a fresh checkout, then **Check GPU environment**. Setup installs only under `Tools/SplatWorker`; it does not replace the system Python, driver, CUDA toolkit or Visual Studio. This first Windows profile expects VS 2022 Build Tools and CUDA 12.8 at their standard installation paths. CPU source inspection remains usable when the GPU check fails. Initial CUDA compilation can take several minutes. Cancellation is cooperative; an in-progress native compilation or CUDA call must return before it is observed.

Jobs write requests, status, heartbeat and logs to `SplatData/jobs/<job-id>`. Complete results are atomically published under `SplatData/results/`, with a `current_<operation>.json` pointer. Reopening the window or reloading scripts reattaches to the recorded worker PID and creation time; it never restarts the request. A worker that dies without a terminal result becomes **Interrupted**. Use **Open job logs** for `stderr.log` and `error.log`; use the setup log at `SplatData/setup/setup.log` for dependency failures. Do not start another GPU process in the same data workspace while one is active.

If a crashed compilation leaves a PyTorch build lock, the next GPU check uses a fresh build directory. It leaves the abandoned directory untouched because compiler child processes may still own those files. A successful build becomes the reusable cache. Native compilation cancellation remains cooperative.

The renderer is `wu.yize.gsplat` 1.4.0 at commit `a2bf458d6b16395e6570e9345f9f4408f92684b8`. Desktop uses Direct3D12, URP Render Graph, and the Gsplat URP feature in `PC_Renderer`. The reference importer uses **Uncompressed**, **RUB** source coordinates converted once to Unity, and **opacity pruning 0**. The renderer uses SH0, gamma-to-linear conversion for the Linear project, complete upload before rendering and sorting every frame. Spark remains the intended later Android profile; it is not being presented as the uncompressed reference.

The local source is `ScottVickers_CleanUp.ply`: **6,011,316 splats**, 336,634,059 bytes, SHA-256 `7351c4694b28360c8898c47f799a63e8b69fb941eac0a62a830a407cf044605d`. Its original file is untouched. The generated copy is at `Assets/SplatPreprocess/Generated/ScottVickers_CleanUp.ply`. That large PLY is ignored by Git, while its `.meta` is tracked to preserve the scene reference. On a fresh checkout, restore a byte-identical source copy to that exact path; Unity will use the committed importer settings and GUID. Do not replace the `.meta` file.

The scene's new **Stage 1 Workspace** root contains the full-source renderer and a disabled **Stage1 Inspection Camera (Optional)**. The model has translation `(-3.254876, 3.2300894, 9.156104)`, rotation zero and scale one. This is preview placement, not a physical meter calibration. A known real distance and matching source endpoints are still required. The original rig, locomotion, collision and input handlers are owned by the user and have not been replaced. In Edit Mode its camera sits at floor level, so existing scene objects can obstruct the view; the optional inspection camera provides a clear diagnostic view without taking over the Game camera.

Local evidence is in `SplatData/validation/m0/` and `SplatData/validation/m1/`. The GPU check compiles the pinned gsplat 1.5.3 source and verifies finite RGB/alpha plus a known one-splat opacity. It is a backend correctness check, not a six-million-splat CUDA benchmark or an Android performance claim. Android maximum count, sustained frame timing and stereo behavior still need the exact target device and the user's VR setup.

Run worker tests with `& .venv/Scripts/python.exe -m pytest -q` in PowerShell from `Tools/SplatWorker`. Unity EditMode tests are in the `SplatPreprocess.EditMode.Tests` assembly. The manual domain-reload fixture is `python -m tests.reload_probe <request.json>`; it is a test helper, not a supported production job operation.
